# Backend

- **Domain:** gssc5 backend (Elysia/Bun/Prisma) — SoftDev/TestDev plans use `bun test` / `mise run //backend:test`, not Angular/`ng test` and not LangGraph Python packaging.
- App: `gssc5-web/apps/backend` (Elysia + Bun + Prisma).
- Auth session: durable `login_tokens` rows; hash via `hashLoginToken` (`Bun.CryptoHasher` sha256); cookie name `gssc_login_token`. Login/recovery opaque tokens from Web Crypto `crypto.getRandomValues`; `/challenge` returns via Elysia `status(200, …)`.
- Cookie I/O through Elysia cookies (`loginTokenCookie`, `setLoginTokenCookie`, `clearLoginTokenCookie` in `src/user/login-session.ts`) — httpOnly, secure, sameSite lax, path `/`.
- Authenticated user resolve (cookie → hash → `loginToken.findUnique` → classify → user payload) goes through shared `resolveLoginSessionUser` in `src/user/login-session.ts`; pass a Prisma user `select` (or omit for full `User`). Do not reimplement beside route modules.
- KVS: `src/kvs.ts` for key/value storage used by frontends.
  - Content (webpage generic content): `src/content/section.ts` (`/sections`), `src/content/announcement.ts` (`/announcements`; list merges in-window events per BHLR-147/148), `src/content/template.ts` (`/templates`), `src/content/events.ts` (`/events`), `src/content/research-tools.ts` (`/research-tools`, plus `POST|GET /research-tools/:cuid/file`), `src/content/publications.ts` (`/publications`), `src/content/newsletters.ts` (`GET|POST /newsletters`, `GET|PATCH|DELETE /newsletters/:cuid` with `/newsletter/:cuid` alias), `src/content/newsletter-files.ts` (`POST|GET /newsletter-files` — dedicated `newsletters/{cuid}` store; GSSC5-142 / BLLR-493..495), shared `src/content/helpers.ts` (`includesInsensitive`, `parseKnownQuery`). App wires `.use(section).use(announcement).use(template).use(events).use(researchTools).use(publications).use(newsletters).use(newsletterFiles).use(files)`.
  - Mutation bodies (GSSC5-64 / GSSC5-111): section/template/research-tools/publications/events/newsletters declare Elysia `t.Object` schemas composing Prismabox scalar fields (`.model` + `additionalProperties: true` like KVS). Wire keeps `cuid` and string[] tags/resources/keywords — do not drop in raw `*Plain` (those expose `id` and JSON-string tags/keywords).
  - Prisma: `page_data` (datatype `section` | `announcement` | `event`; shared `index`/tags/perms; optional inclusive `startMonth`/`startDay`/`startYear` and `endMonth`/`endDay`/`endYear` for display windows on announcements/sections and event spans — single-day events use equal start and end; GSSC5-67 / BLLR-400–401; optional `imageFile` StoredFileEntry cuid + `imagePosition` `none`|`left`|`right` GSSC5-74), `Event` mapped to `events` (name, event date Y/M/D, announcement-window start Y/M/D, time, duration, location, isPublic, perms, `pageDataId` → event-details row; GSSC5-69), `ContentTemplate` mapped to `page_templates`, `ResearchTool` mapped to `research_tools` (cuid, title, referenceLink empty when file-backed; GSSC-188), `Publication` mapped to `publications` (cuid, title, referenceLink, optional description), `Newsletter` mapped to `newsletters` (cuid, volume, number, month, year, filePath StoredFileEntry cuid, keywords JSON string array; GSSC5-20), and `StoredFileEntry` mapped to `stored_file_entries` (file/folder tree + DB ACLs; GSSC5-71).
  - Research tool files (GSSC-188 / BLLR-496..500): `research-tools/` under `FILE_STORAGE_ROOT` + DB folder on init; `POST /research-tools/:cuid/file` stores/overwrites by tool cuid (clears `referenceLink`); public `GET /research-tools/:cuid/file`; setting a non-empty URL soft-deletes the stored file; wire entries include `hasFile`.
  - Event date mapping (GSSC5-69): event `month/day/year` mirrors onto linked `page_data` `start*`/`end*` (equal for single-day). Announcement-window start stays on `events` only — not parallel columns on `page_data`.
  - Event list/get wire (GSSC5-30): `GET /events` and `GET /events/{cuid}` include linked page_data `header`/`body`/`resources`/`start*`/`end*`/`imageFile`/`imagePosition` with catalog fields so the public calendar needs no second fetch (BLLR-414/415/417).
  - Perm integers (page data / events): bit 0 (`0o1`) regular member, bit 1 (`0o2`) user moderator, bit 2 (`0o4`) tool editor, bit 3 (`0o10`) publication editor, bit 4 (`0o20`) newsletter editor; admin always allowed (BLLR-332/342; GSSC5-141). Event create without template defaults create/modify/delete to user-moderator bit.
  - Research tools mutations require `isToolEditor` or admin (GSSC5-18). Publications mutations require `isPublicationEditor` or admin (GSSC5-19). Newsletters mutations require `isNewsletterEditor` or admin (GSSC5-20) — separate from publication editor.
  - Files (`src/files/`): local FS under `FILE_STORAGE_ROOT` (default `./data/files`); DB ACL `isPublic` + `readRoles`/`writeRoles` JSON role tokens (`member`, `userMod`, `toolEditor`, `publicationEditor`); inherit parent ACL; reject looser child; soft-delete only. Routes: `GET/POST /files`, `POST /files/upload`, `GET/DELETE /files/:cuid`.
  - Account photos (GSSC5-101 / BLLR-453..458): `src/user/account-photos.ts` ensures `account-photos/` under `FILE_STORAGE_ROOT` + DB folder on init; `POST /account-photos` stores/overwrites by target **user cuid** (`userCuid` form field, default session user); `GET /account-photos/:cuid` resolves cuid-named (or legacy id) entries; GET allowed with valid login token **or** when a user stores that cuid / owns that id and has a non-empty `position`; users API projects/persists `accountPhoto`. Account Information POST must send string `accountPhoto` (empty clears) — `null` 422s in `buildPatch`.
  - Newsletter issue files (GSSC5-142 / BHLR-239 + BLLR-493..495): `src/content/newsletter-files.ts` ensures `newsletters/` under `FILE_STORAGE_ROOT` + DB folder on init; `POST /newsletter-files` multipart `{ file, newsletterCuid }` for newsletter editor/admin; stores/overwrites as `newsletters/{newsletterCuid}` (entry id/name = newsletter cuid, `isPublic`); sets `Newsletter.filePath` to that cuid; replace soft-deletes prior path/sibling entries and removes superseded bytes; `GET /newsletter-files/:cuid` serves public issue bytes (catalog also still resolves via `GET /files/{filePath}` when filePath is the cuid).
  - LLR shape: Service Transactions → Webpage Content → Generic Content → Sections|Announcements|Templates → URI → HTTP method (collection GET/POST; item GET/PATCH/DELETE); Events, Research Tools, Publications, Newsletters, and Files parallel under Webpage Content.
  - Data Storage LLR children: Users, Password History, Key-Value, Generic Content, Events, Research Tools, Publications, Newsletters, File Storage.
- User/account/password modules under `src/user/`. Site privileges include `isAdmin`, `isUserMod`, `isToolEditor`, `isPublicationEditor`, and `isNewsletterEditor`. Prefer `status()` patterns from project prefs; Prismabox for generated models; Argon2id for password hashes. Login and password-recovery bodies (`accounts.ts` LoginBody.primaryEmail; `passwords.ts` RecoveryRequestBody.email / RecoverBody.primaryEmail) use Elysia `t.String({ format: 'email' })` — do not reintroduce a duplicated `emailPattern`; keep the login union error text.
- User soft-delete (GSSC5-102 / BHLR-223..224 + BLLR-459..466; CHANGE_DRIVER on BLLR-41; API hygiene GSSC5-104): `users.deletedAt` optional marker; GET `/users` omits soft-deleted unless caller is admin (admin projection includes marker); admin soft-delete via `DELETE /users/{cuid}` (alias `POST …/soft-delete` one cycle) sets marker; `POST …/undelete` clears it; non-admin rejected; user update via `PATCH /users/{cuid}` (alias `POST` one cycle); combined `name` filter (first|middle|last) and `address` filter (home city|state only). SoftDev/TestDev: backend.
- Admin create member (GSSC5-119 / **BHLR-237** + **BLLR-485..487**): `POST /users` body username, primaryEmail, password, optional first/last; 201 projected user; 403 non-admin; 422 invalid/duplicate. SoftDev/TestDev: backend.
- Invite member (GSSC5-118 / **BHLR-238** + **BLLR-488..490**): `POST /users/invite` with primaryEmail required, optional username/first/last; creates account with unusable random password hash; invitation email with password-recovery-style token (reuses recovery token storage); 201 projected user; 403 if caller is not userMod (admin ⊃ userMod); 422 invalid/duplicate. SoftDev/TestDev: backend.
- API hygiene (GSSC5-104): `GET /` returns JSON health/version/capabilities (not “Hello Elysia”); catalog list GETs share optional filters + unknown-key `422 Invalid`; newsletters item under `/newsletters/{cuid}` (singular `/newsletter/{cuid}` aliased); create returns `201` for research-tools/publications/newsletters/files; files/account-photos errors use literal `"Forbidden"`/`"Not Found"`/`"Invalid"` with missing session `403`; files soft-delete success `204`. Sort/pagination (Batch C) deferred.
- Site trees (GSSC5-40 / BHLR-225..230 + BLLR-467..475, 483..484; seed destinations GSSC5-130; uninitialized-only seed GSSC-181): `SiteTree` / `SiteTreeNode` (`site_trees` / `site_tree_nodes`) per frontend (`public`|`members`); `src/content/site-trees.ts` — `GET /site-trees/:frontend` nested JSON; admin `POST /site-trees/:frontend`, `PATCH|DELETE /site-trees/:frontend/nodes/:nodeId`; idempotent `seedSiteTrees` / `ensureTree` (also `prepareDevDatabase` / module `onStart`) — creates a frontend tree only when uninitialized (no `SiteTree` row); `PUBLIC_SEED_CHILDREN` / `MEMBERS_SEED_CHILDREN` match current public routes and members header/editor destinations on first seed; later boots leave initialized trees untouched (no additive re-add of admin-removed nodes); path hints for menus only — no Angular route registration. SoftDev/TestDev: backend.
  - Site-tree mutation/entry schemas (GSSC5-113): `CreateNodeBody`, `UpdateNodeBody`, and `SiteTreeNodeEntry` compose `SiteTreeNodePlain` / `SiteTreeNodePlainInputCreate` scalars (`.model` + `additionalProperties: true` like publications). Wire keeps `cuid` not raw `id`; `parentId` and `sectionTag` stay string-or-null. Do not drop in raw `SiteTreeNodePlain` (exposes `id` + relations).
- Site search (GSSC5-106 / BHLR-231..236 + BLLR-476..482): `GET /search` (`src/search.ts`) with `q`, `frontend` (`public`|`members`), optional `limit`/`kind`; public corpus unauthenticated; members corpus requires login cookie; result projection `{ title, snippet, href, kind }[]`. Corpus: site-tree stubs (`src/content/site-tree-stub.ts`; real SiteTree rows from GSSC5-40 not yet wired into search), page-data header/body with public/session visibility, catalogs (publications/research-tools/newsletters/events/announcements), members directory display names when session permits. SoftDev/TestDev: backend.
- Tests: `src/test-harness.ts`; `*.test.ts` beside sources; `mise run //backend:test`.
- Dist: `gssc5-web/dist/backend`.
